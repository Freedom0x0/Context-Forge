# 面向 Agent 的持续学习记忆系统

> **2026-09-22 变更**：召回边界模型已更新，见 `.trellis/tasks/09-22-falsifiable-memory-recall/` 与 `docs/technical-design-falsifiable-memory.md`。
> 要点：`project` 默认只作来源（provenance）和弱排序，移出默认硬过滤路径；项目级访问限制改由显式 `AccessPolicy` 表达；自动沉淀与有依据的修正为主流程，人工阅读/修改/抑制/删除是可选旁路。本文档以下与 `project` 硬过滤、人工闸门相关的表述以新文档为准。

## 产品定位
从经历中形成有依据的理解，在新任务中应用，并根据结果修正。
学习由 Agent、工具和记忆服务共同完成；数据库承担持久化与检索，不宣称数据库自主思考或模型参数发生训练。
2026-09-21 用户已授权实施，memory-store 首先进入 in_progress。此前自动记忆、SQLite 权威存储、按需检索和人工纠正的决策继续有效。

## 用户价值
让 Agent 在跨任务中保留有效理解、识别适用边界并纠正错误。成功标准是后续决策改善，而非条目数量或模型自信增长。
系统不依赖人工逐条审核；人工能够纠正、限制使用和要求遗忘。用户偏好与可验证事实分开保存，不将任何来源自动等同真理。

## Requirements
- R1 观察与解释分离：保存观察来源和内容，推断明确标注为推断；证据缺失保存未知。
- R2 理解有边界：记录判断的适用条件、支持/反对证据、来源与版本；新信息可补充、细化、反驳或替代，不能一律覆盖。
- R3 验证有归因：工具结果、模型判断和人工意见区分来源；任务成功不自动证明所有参与记忆正确，重复转述不算独立证据。
- R4 按需应用：通过 MCP/CLI 获取相关理解及限制条件；临时进入当前请求上下文，不永久注入所有请求，不训练模型参数。
- R5 结果驱动修正：对比预期和实际结果，只有关联证据足够时修改判断、范围或状态；无法归因时保持未决。
- R6 自主但有边界：现有模型网关自动提炼零到多条记忆，允许不产出、不更新和保留冲突；模型不可用时查询仍可运行。
- R7 人工纠正旁路：支持抑制、恢复、修改、范围调整、替代和撤销；明确使用约束不能被后台模型静默推翻。
- R8 不盲从历史或用户陈述：当前任务意图与事实判断分开。明确要求直接执行；仅影响实质决策且信息不足时澄清，不重复询问已解释选择。
- R9 SQLite memory.db 是长期权威来源，FTS5 可重建，queue.db 保留运行队列，Markdown 为导出视图。
- R10 版本、来源、关系和状态事务一致；迁移可重试、可恢复；保留策略支持明确遗忘，不永久保存全部私人会话。
- R11 召回、返回、呈现、引用、采用和验证分开记录，曝光不能自动提高可信度。
- R12 评估学习效果、过度泛化、错误延续和成本，不以记忆数量或候选数量为验收目标。

## Acceptance Criteria
- [ ] 无人工审核可完成观察、提炼、保存、检索、结果记录和有依据的修正。
- [ ] 每条有效理解能解释来源、适用条件、证据强弱和修改原因。
- [ ] 不把模型重复总结、曝光次数或无归因成功当成独立验证。
- [ ] 新证据能够收窄或修正理解；未知条件不被当成满足，历史依据仍可追溯。
- [ ] 查询保留相关限制与冲突，不跨项目泄露；相同快照/查询/参数排序稳定。
- [ ] 人工抑制不被后台任务复活，并发修正不会丢失。
- [ ] 事务故障与跨库重试无重复发布或半提交；备份可恢复全部权威数据。
- [ ] 旧 vault 导入不改内容/mtime，重复导入不覆盖新纠正。
- [ ] 端到端证明宿主在需要时检索；只证明 MCP 可调用不算完成。
- [ ] 按研究协议报告收益、错误率、延迟和 token 成本；模型不确定性如实披露。
- [ ] 项目全量测试通过。

## Out of Scope
模型参数训练、专用向量数据库、无界自主研究、自动执行记忆中的危险操作、强制人工审批、通用人格或意识模拟。
